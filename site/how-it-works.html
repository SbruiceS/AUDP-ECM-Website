Mathematics & conventions

How AUDP-ECM works

The exact finite-field conventions, code construction, decoding guarantees and framing rules, so results can be verified independently and implementations can interoperate.

1 · The finite field GF(28)

  • Symbols are bytes, interpreted as elements of GF(28) = GF(2)[x] / p(x) with the primitive polynomial p(x) = x8 + x4 + x3 + x2 + 1 (0x11D).
  • Bit i of a byte is the coefficient of xi. The primitive element is α = x (byte 0x02); every non-zero element is αe for a unique 0 ≤ e ≤ 254.
  • Addition is bitwise XOR. Multiplication is polynomial multiplication reduced modulo p(x), for example 0x53 · 0xCA = 0x8F and 0x80 · 0x02 = 0x1D.

3 · Generator polynomial and systematic encoding

The generator has the r consecutive roots α1 … αr (first consecutive root b = 1):

g(x) = (x − α)(x − α2) ··· (x − αr),   deg g = r, monic.

For data bytes m0 … mk−1, with m(x) = Σ mj xj, the codeword is

c(x) = xr·m(x) + p(x),    p(x) = xr·m(x) mod g(x).

Byte layout: byte j of the transmitted codeword is the coefficient of xj. The r parity bytes come first (j < r), followed by the k data bytes unchanged. Every codeword satisfies c(αi) = 0 for i = 1 … r.

4 · Decoding

  1. Syndromes Si = y(αi), i = 1 … r, of the received word y. All zero ⇔ y is a codeword, so no correction is needed.
  2. Error locator Λ(x) from the key equation S(x)·Λ(x) ≡ Ω(x) (mod xr), solved by the Berlekamp–Massey algorithm. An independent Euclidean-algorithm decoder solves the same equation and is cross-checked against it in testing.
  3. Erasures (known-bad positions) enter as the erasure locator Γ(x) = Π (1 − αjx) through modified (Forney) syndromes. The combined errata locator is Λe(x)·Γ(x).
  4. Chien search: error positions are the j with Λ(α−j) = 0. The number of roots must equal deg Λ.
  5. Forney's formula gives each error value: ej = Ω(α−j) / Λ′(α−j).
  6. Verification: a result is returned only if the corrected word is a valid codeword. Otherwise decoding fails with an explicit error.

Guarantee. With e unknown errors and s erasures, decoding is unique and correct whenever 2e + s ≤ n − k. An erasure costs one parity byte; an unknown error costs two.

5 · Correction limits: what happens beyond capacity

When 2e + s > n − k, no decoder can guarantee the original data. Exactly one of three things happens:

Rejected (most common)

No codeword lies close enough to the received word. Decoding fails with an explicit error, so the frame is detected as bad and never silently accepted.

Miscorrected (rare)

The damage moved the word within t symbols of a different valid codeword, which the decoder then returns. This is a fundamental property of every error-correcting code, not an implementation bug.

Caught by CRC

Burst framing adds a CRC-16 over the payload. A miscorrection must also pass that 16-bit check, so wrong payloads are rejected except with probability about 2−16.

Measured: across 1,800 test frames with exactly t + 1 errors, using codes with 2–32 parity bytes, 98.4 % were rejected and 1.6 % miscorrected before any CRC. Miscorrection becomes rarer as the parity count grows. You can reproduce both outcomes in the live demo by corrupting more than t symbols.

Erasure caveat: each marked erasure consumes budget. Marking too many positions as unreliable can turn a correctable frame into an uncorrectable one, so marking is bounded to n − k.

6 · Burst-resilient framing and its assumptions

frame = len (u16, big-endian) ‖ payload ‖ CRC-16(len ‖ payload), zero-padded to depth·k bytes

The frame is split into depth consecutive k-byte blocks, each encoded as one RS(n, k) codeword. Byte j of codeword i is transmitted at position j·depth + i. A contiguous burst of L bytes therefore touches at most ⌈L / depth⌉ bytes of any one codeword, so every burst of up to depth·t bytes is corrected.

Recovery returns the exact payload (its length is part of the frame) after the CRC matches. The guarantees assume:

  • Symbol synchronisation: the receiver gets exactly n·depth bytes in order. Insertions, deletions and bit slips are not corrected and must be handled by the link layer.
  • Per-codeword budget: the rule is that every codeword individually satisfies 2e + s ≤ n − k. A single burst of ≤ depth·t bytes always meets it; several bursts in one frame may not.
  • Erasure positions, when supplied, index the transmitted stream. They are mapped to codewords automatically.
  • Payload size ≤ depth·k − 4 bytes and ≤ 65,535 bytes. The receiver buffers n·depth bytes, which adds latency equal to one full frame.

7 · CRC-16 parameters

CRC-16/CCITT-FALSE: polynomial 0x1021, initial value 0xFFFF, no input or output reflection, no final XOR. It is appended big-endian. Check value: CRC("123456789") = 0x29B1. A CRC detects accidental errors; it does not authenticate data (see security model).
