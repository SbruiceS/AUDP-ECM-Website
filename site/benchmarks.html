Reproducible performance

Benchmarks

Latency, throughput and memory of the released v0.2.0 packages, measured on GitHub-hosted runners with a published method. Anyone can rerun them.

Method

  • What is measured: the public API, exactly as applications call it. Python uses the released wheels (checksum-verified); D builds the release tag against the native library version it pins.
  • Operations: encode; decode of a clean word; decode with exactly t errors; decode with n − k erasures; burst framing of a 64-byte payload with one burst of depth·t bytes.
  • Timing: warm-up, then 7 rounds, each a batch sized to about 50 ms. Reported: median and minimum per call. A run is flagged noisy if any operation varies by more than 1.5× between rounds.
  • Memory: Python heap allocated per call (including result objects) and process peak RSS (which includes the Python interpreter); for D, garbage-collected bytes per call.
  • Inputs: seeded (20261020), so every run measures identical data.

Reproduce: run the Benchmarks workflow in the Python or D repository, or locally:

python benchmarks/bench.py            # Python, after pip install audp-ecm
dub run :bench -b release             # D, with AUDP_ECM_LIB_DIR set

Shared CI runners and laptops vary, so compare numbers within one table rather than across machines. Throughput counts payload bytes only.
