Mathematical conventions and guarantees: how it works.

Test methodology

KindWhat it establishesWhere
Known-answer vectorsField arithmetic, generator, codewords and CRC match the published valuescore, Python, D, browser
Exhaustive small casesEvery single-symbol error in RS(7,3), corrected by both decoderscore
Errata budget sweepEvery combination 2e + s ≤ n − k decodes exactlycore, Python, D
Property-based testsRandom messages, error patterns and bursts within capacity always recovercore, Python (Hypothesis)
Differential testsTwo independent decoders agree; table arithmetic equals a reference; language bindings equal the native librarycore, browser (300 cross-checks)
Adversarial and fuzz testingGarbage input, wrong lengths and bad indices produce errors, never crashescore (coverage-guided fuzzing), Python, D
Soundness of verificationAny successful decode returns a valid codeword within the claimed distancecore
Memory-safety checkingThe native boundary is checked under an undefined-behaviour interpretercore CI
ConcurrencyShared decoder objects are safe across threadsPython, D
Release-artifact testsEach built wheel is installed and tested before it is releasedPython CD

Continuous integration runs on every change: Python on Linux, Windows and macOS with Python 3.10, 3.12 and 3.13; D with DMD and LDC on Linux, Windows and macOS. Changes reach the main branch only through reviewed pull requests whose required checks pass.
